# Changelog

## 2026-11-25 — Initial repository analysis and baseline execution

- **Added:** `REPOSITORY_ANALYSIS.md`, `PROJECT_OVERVIEW.md`, `MANUAL_EXECUTION_GUIDE.md`, `INSTALLATION_GUIDE.md`, and `EXECUTION_GUIDE.md` to record repository evidence, current environment, smoke-run procedure, and unresolved blockers.
- **Modified:** `Envs/clusterEnv.py`.
  - Replaced the non-portable original-author macOS dataset paths with source-relative paths so the committed dataset loads on Windows.
  - Removed an unused import of the absent `Envs.utils` module.
  - Made `_check_episode_finish()` explicitly return `False` for an unfinished episode.
  - Updated the terminal observation time to the simulator clock after a final task finishes; this fixes the makespan observation without changing task selection or execution.
- **Reason:** The original environment could not load its checked-in datasets on Windows; it also imported a missing helper, returned `None` for an unfinished episode, and exposed a stale time at terminal state.
- **Validation:** `pip check` reported no broken requirements in the compatibility venv; AST parsing passed for all 21 Python files; direct `clusterEnv` reset/step passed; a complete 30-task episode completed in 60 decisions; the repository SJF helper functions completed one 30-task episode in 60 decisions. Gym `make()` worked after process-local registration with the Gym API checker disabled.
- **Observed smoke values:** First-feasible test driver makespan 234.0; SJF helper makespan 245.0 for the seeded single workflow. These are functional smoke observations, not experimental conclusions.
- **Not completed:** Full PPO training/evaluation; repeated baseline experiments; Matplotlib plotting. TensorBoard and `clusterEnv-v0` registration were resolved in subsequent steps.
- **Scheduling algorithm changes:** None. The final completion reward remains zero and is documented as an unresolved RL return-accounting issue.
- **Added:** `SYSTEM_ARCHITECTURE.md`, `RESEARCH_GAP.md`, and `PROPOSED_APPROACH.md` to document the implemented architecture, evidence-based research gaps, and a clearly separated proposed Edge–Cloud simulator.
- **Updated:** `PROJECT_OVERVIEW.md` with links to the research documents and the workload-generator discrepancy.
- **Architecture findings:** The active generator creates CPU and memory demands from the same 25%–50% range, while the README describes differentiated task classes; its active default duration probability also differs from the README's stated distribution. The terminal environment branch reports final time but does not release/remove the final task from internal pending state.
- **Validation:** Source-level claims were checked against `Envs/clusterEnv.py`, `DAGs_Generator.py`, and `PPOagent.py`; `git diff --check` passed. No new simulator or scheduling behavior was implemented.
- **Follow-up execution:** Installed TensorBoard 2.19.0; cluster environment registration and an eight-transition PPO update passed. Existing checkpoint inference completed one 30-task episode in 60 decisions (makespan 198.0); checkpoint provenance is unknown.
- **Decision:** Preserve original terminal reward behavior for the baseline and postpone full training/evaluation pending review of the omitted final time cost. No reward or scheduling code was changed.
- **Edge–Cloud prototype:** Added `Envs/edge_cloud_simulator.py`, a separate deterministic simulator for heterogeneous nodes, task-scoped pod records, DAG constraints, FCFS/SJF selection, and configurable link delays. It does not modify or replace the original `clusterEnv`.
- **Tests:** Added `tests/test_edge_cloud_simulator.py`; four tests pass for task precedence/resource release, hand-computed network delay, cycle/missing-link validation, and unschedulable resource requests. The network test confirms 2 runtime + 3 transfer delay + 2 runtime = makespan 7.
- **Prototype limitations:** No experiment runner or config loader, bandwidth contention, transfer overlap, pod reuse/lifecycle, staleness, metrics export, or Kubernetes integration. Node busy-time ratio is not capacity-normalized utilization.
- **Extended prototype:** Added JSON workload configuration `configs/edge_cloud_example.json` and `edge_cloud_experiment.py`, which runs FCFS and SJF and writes CSV metrics. CPU/memory utilization now uses resource-time divided by node capacity and makespan.
- **Extended evaluation:** Added a minimum-estimated-finish-time policy and paired seeded repetitions with optional bounded duration jitter; each policy sees the same workload realization per replicate.
- **Validation:** Six simulator/runner tests pass, including deterministic repeatability under identical seeds. Example workflow forces Edge/Cloud placement; FCFS/SJF/min-finish complete all tasks (makespan 35.0, communication delay 17.0, 14 data units transferred); CSV was emitted to a temporary path. This is a functional check, not a result comparison.
- **Limitation:** No confidence intervals/statistical analysis yet; synthetic duration jitter is not a substitute for validated workload traces.
- **Repeated smoke run:** 20 paired runs (seeds 100–119, ±10% uniform task-duration jitter) produced mean makespan/sample SD: FCFS 35.292/0.672, SJF 35.292/0.672, min-finish 25.917/0.626. These are tiny synthetic-example pipeline values, not scientific performance evidence; CSV stayed in the system temporary directory.
- **Policy test:** Added a test showing FCFS and SJF choose different tasks when a long and short task are simultaneously ready on a capacity-constrained node. Seven simulator/runner tests now pass.
- **Statistics export:** Replaced the rough normal-approximation interval with a reproducible percentile-bootstrap 95% interval over replicate makespans. It remains descriptive and does not test paired policy differences.
- **Paired comparison:** Summary CSV now also reports per-seed paired makespan differences against FCFS and bootstrap intervals over those paired differences.
- **Placement constraints:** Tasks may now specify eligible tiers (`edge`, `cloud`); infeasible tier constraints are rejected at scheduling time. FCFS/SJF tie-break using the configured task order rather than lexical task IDs.
- **Validation:** Eight simulator tests pass, including allowed-tier placement and impossible-tier unschedulability.
- **Workload integration:** Added a loader for the repository's pre-generated DAG, duration, and demand arrays, with selected size/index and explicitly synthetic uniform edge data-size input. Added a cluster-capacity config for those demand scales.
- **Validation:** Ten tests pass. A selected 10-task repository DAG completed under all three policies in a two-replicate smoke run; raw and summary CSV were written to temporary files. With no duration jitter, repeated runs of the same selected DAG are intentionally identical.
- **Multi-workflow evaluation:** Runner now supports multiple selected dataset indices; policy comparisons are paired within workload and jitter replicate. It verifies all tasks complete and node CPU/memory return to capacity.
- **Observed exploratory batch:** Ten committed 50-task workflows x two paired duration-jitter replicates; every policy completed. Mean makespan FCFS 216.852, SJF 237.200, min-finish 227.188; paired differences vs FCFS +20.348 and +10.336. Synthetic data-edge size=1, selected training workflows, and small sample mean these are not research conclusions; outputs were temporary.
- **Held-out workload support:** Added test-split loading. A 20-workflow 50-task test-set smoke batch completed for all policies with synthetic edge payload=1; means FCFS 205.936, SJF 233.795, min-finish 229.856. Paired deltas and bootstrap intervals were computed; outputs were temporary and are documented strictly as exploratory because workload provenance and network payloads are not validated.
- **Correctness coverage:** Added multi-parent transfer test (child starts after the latest parent-plus-transfer), held-out loader check, and completion/resource restoration invariants in the experiment runner.
- **Observation and pod lifecycle:** Added optional fixed-delay snapshots of node free capacity and a stale minimum-finish policy; per-task pod records now track node and pending/running/completed state. Added tests for stale-observation waiting and transfer-ready events independent of task completions. A 20-workflow, 5-unit observation-delay smoke comparison completed; stale policy mean makespan was 28.351 units above fresh min-finish (paired 95% bootstrap interval 18.292–38.527). This only verifies behavior under an arbitrary simulator assumption; no real telemetry or policy quality claim follows.
- **Full held-out collection:** Ran all 1,000 50-task held-out array entries with synthetic edge payload 1 and no duration jitter. Means: FCFS 204.037, SJF 223.466, fresh min-finish 220.470. With 5-unit observation delay, stale min-finish's paired mean difference vs fresh min-finish was +30.330 (95% paired bootstrap CI 28.971–31.711). All tasks completed in every run; temporary outputs were removed. Dataset provenance, network assumptions, node settings, and model simplicity prevent scientific superiority claims.
- **Sensitivity reporting tools:** Added a full-factorial runner over payload size, observation delay, link-condition scaling, and node CPU/memory capacity scaling. It exports scenario-level summaries, per-DAG raw CSV, and a timestamped scenario log. Added `generate_sensitivity_report.py` to generate a report and SVG figures without a plotting-library dependency.
- **Completed sensitivity report:** Evaluated 16 configurations x 1,000 DAGs x 4 policies (64,000 rows). All runs completed. Unweighted scenario-mean makespans were FCFS 218.471, SJF 238.329, fresh minimum-finish 234.974, stale minimum-finish 251.536. At 5-unit delay, stale minimum-finish marginal mean was 33.124 units above fresh minimum-finish. Full raw/summary CSV, log, report, and two SVGs are retained under `results\` and repository root. These are assumption-sensitivity results only; see report limitations.
- **Additional simulator checks:** Added tests for simultaneous execution of independent tasks, capacity-normalized utilization reaching 1.0 at full load, and rejection of reusing a consumed simulator instance. These historical checks brought the suite to 13 tests before later lifecycle, sensitivity, and report tests.
